Running as a service #

Step-by-step guides for Debian and Ubuntu, Arch, Fedora and macOS are in Run the proxy as a service. This page is the short reference.

maple-harness service keeps the proxy and the remote gateway running in the background and starts them when you log in. On Linux it writes systemd user units; on macOS, launchd agents. Nothing runs as root and nothing is installed system-wide. Windows is not supported.

maple-harness service install            # the proxy and the gateway
maple-harness service install proxy      # one of them
maple-harness service status             # installed? running?
maple-harness service print gateway      # show what would be written; write nothing
maple-harness service uninstall          # stop and remove what install wrote

You do not need this to use the agent: it starts the proxy itself, and /remote starts the gateway. Install a service when you want the phone to work without a session open, or the proxy running before you open a terminal.

  • Logs. Linux: journalctl --user -u 'maple-*' -f. macOS: ~/.config/maple-harness/run/maple-<name>.log.
  • Start at boot, not at login (Linux). loginctl enable-linger $USER.
  • After moving or reinstalling the binaries, run service install again so the unit points at the new path.
  • A file you edited is left alone unless you pass --force.
  • In a container or an SSH session with no user manager, install says so and writes nothing; use service print and place the file yourself.

The files hold no secret. Tokens and keys are read from where they are always kept.
