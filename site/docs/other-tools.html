What the proxy adds for other tools #

Claude Code, OpenCode, pi, GitHub Copilot CLI, Hermes and Codex CLI can send their requests through the Maple proxy instead of straight to a provider. Use your models from other tools has a tested setup for each. This page says what they get from it, and what stays in Maple Harness.

Other tools that speak the OpenAI or Anthropic API can use the same addresses: Cursor, Gemini CLI, Qwen Code and Crush are covered below, without a tested setup. Programs that start and steer agents (orchestrators) are covered in Orchestrators.

Everything below describes what the proxy does. Nothing here is a promise about your bill.

The short version

In plain words #

  • What it is. Claude Code, OpenCode, pi, Copilot CLI, Hermes and Codex can send their requests through the Maple proxy instead of straight to a provider. Other tools that let you change their model address can too.
  • Why you want it. They get every model the proxy serves, its fallbacks when an account runs out, its budgets, and their usage on the same charts as Maple's.
  • What to do. Point the tool at the proxy's address (Addresses, at the top of the setup page, shows both with a Copy button); the tested lines for each tool are in Use your models from other tools.
  • Orchestrators. A program that opens agents in terminal panes, hands them tasks and watches them can do the same with Maple Harness: start it with a task, list and resume its sessions, read its state, send it messages, answer its approvals, and count cost per task. Nothing in Maple Harness is written for one orchestrator; the same commands serve all of them.

One address for many models #

The tool asks for a model by name, and the proxy sends the request to whichever provider serves it: your GitHub Copilot account, an Anthropic account, or a model server such as Ollama, LM Studio or oMLX. The proxy translates between the two APIs in both directions. Claude Code, which speaks the Anthropic API, can use a Copilot model or a local one. OpenCode, pi, Copilot CLI, Hermes and Codex, which speak the OpenAI API, can use a Claude model from an Anthropic account.

Give the tool a name the proxy lists (curl http://127.0.0.1:11535/v1/models), or an alias from model_aliases. You can then change which model an alias means without touching the tool. See Model aliases.

A tool can also ask for the proxy's auto mode: with the model auto, the proxy looks at each request and sends it to a heavy, medium or light model; auto-heavy, auto-medium and auto-light fix the weight. Each means a model and its fallbacks, from your provider's own ranking unless you choose them on the setup page's Auto mode card. The proxy judges from the request alone, so it does not know what the tool meant; X-Maple-Router says how it weighed a request and X-Maple-Served-By which model answered. The proxy's log, the usage log and both headers are described in See what auto chose.

A tool can also ask for github-copilot/auto, where GitHub Copilot itself picks the model for each request, when your Copilot account offers it. The X-Maple-Served-By header says which model Copilot picked. It can also be the model for a weight of auto mode, chosen on the setup page's Auto mode card. See Copilot Auto.

Keeps going when an account runs out #

Fallbacks apply to every request through the proxy, whatever tool sent it. With model_fallbacks, a model that cannot answer (out of chats or credit, overloaded, unreachable) hands the request to the next name on its list. provider_fallbacks moves one account's requests to another account. A model that has just said it is out of quota is tried last for the next hour, so the tool does not wait for the same refusal on every request.

A fallback happens only before any output reaches the tool, and never for bad credentials or malformed requests. The usage log's fallback column and the X-Maple-Served-By response header say which model answered. See Fallbacks.

Budgets #

A daily limit on a provider (requests, AI units, or both) counts every request to that provider through the proxy, whichever tool sent it. At the limit, requests are refused or handed to a fallback. See Daily budgets.

See what each tool spends #

Every request through the proxy gets one line in the usage log: the model asked for and the model that answered, tokens in and out, tokens read from and written to the cache, AI units when the provider reports them, and estimated cost and savings columns. The log keeps counts and labels, never prompts or answers. You can query it with DuckDB, or export it to CSV or Parquet (Your usage data).

To tell tools apart:

  • agent is taken from the tool's User-Agent. Claude Code shows as claude-code, OpenCode as opencode and Codex as codex. pi, Copilot CLI and Hermes show as other.
  • client is the label of the access token a tool used. That is the reliable way to separate tools on other machines, or two tools that both show as other: give each one its own token.

The Cache card (hit rate and cache tokens, per model and per client) and the Savings card (what the proxy's own settings saved and cost, each figure marked measured or estimated) include these tools' requests. The Sessions card does not. It groups requests by a session id that Maple Harness sends and these tools do not.

Prompt cache #

Providers charge less for the start of a request they have already seen. For Claude models, reached through an Anthropic account or through Copilot, the provider caches only the parts of a request that are marked for caching. The proxy marks them (prompt_cache, on by default):

  • Claude Code marks its own system prompt. The proxy keeps those marks and marks the conversation too.
  • OpenCode, pi, Copilot CLI, Hermes and Codex, on the OpenAI-compatible address, get the proxy's marks.

The prefix stabiliser (prefix_stabilizer, on by default) keeps the start of each request the same from turn to turn, so a provider's cache can keep matching it. It works with any provider, and each response that it changed carries X-Maple-Prefix-Stabilized. It leaves a request alone when the tool marks its own cache points, so it does not touch Claude Code's requests.

Whether a request hit the cache is in the usage log and on the Cache card. See Caching.

Settings you can turn on #

These are off by default. When on, they apply to every tool.

  • Image shrinking (image_resize_tool, image_resize_user, image_superseded) sends smaller images. Small text in a screenshot may become harder to read.
  • Snapshot trimming (snapshot_trim) shortens browser page snapshots from Playwright MCP. It only acts on results it recognises as snapshots.
  • Trim old tool results (context_trim) replaces old, large tool results in long conversations with a short note. The model can no longer see what was trimmed.
  • Context guard (context_guard) drops the oldest turns, or refuses the request, when a request is too big for the model's window.

See Images and browser snapshots and Guards.

The response cache (response_cache) is different. It answers only requests that carry the header X-Maple-Cache: allow, and none of these tools send it. It also never answers a request whose last message is a tool call or a tool result, and in an agent's loop most requests end with one.

Embeddings are served at http://127.0.0.1:11535/v1/embeddings, for any tool or script that asks for them. See The proxy's cache.

Using it from another machine #

To reach the proxy from another machine, give the tool an access token as its API key, in place of the placeholder. The token's label then names the tool in the usage log's client column. The setup page itself is reachable only from the proxy's own machine, and you can protect it with a password. See Using it from another machine.

What stays in Maple Harness #

These belong to the agent, not the proxy. Pointing another tool at the proxy does not give it any of them:

  • history_search over earlier conversations, and the session journal of what each turn read, changed and ran.
  • Memory notes and the project index as the agent uses them: recalled during a turn, and kept current after each edit. Other tools can reach the notes and the index through a separate server: Give other tools this project's knowledge.
  • The shell sandbox, permission modes and file-access rules.
  • /model auto, which picks a model for each message.
  • /cost and /savings for one session, and the Sessions card, which needs the session id the agent sends.
  • Remote control from your phone.
  • Subagents.

Orchestrators #

An orchestrator is a program that starts agents in terminal panes, hands each one a task, watches whether it is working, waiting for you or done, and carries on from there. MAPLE is one; herdr hosts the panes and shows their state. Maple Harness has no code for any one orchestrator: it offers the same commands and files to all of them, and an orchestrator adds Maple Harness to its own list of agents. This section is what it can use.

In plain words:

  • Start it with a task, and let it work in a pane of its own.
  • Find, read and resume its saved sessions.
  • See its state and send it messages while it runs, as another program on the same machine.
  • Answer its approvals from the orchestrator, if you turn that on.
  • Count what each task cost in the proxy's usage log.
  • Run your project's Claude Code hooks, so an orchestrator's gates hold here too.

herdr. Inside a herdr pane, Maple Harness reports its state (working, blocked, idle), a done: or waiting for approval: line, and its session's name, model and mode, and the agent can open panes, run commands in them and start other agents beside itself. See Use it with herdr; in tmux, WezTerm and kitty, see Use it with tmux.

The agents an orchestrator starts. Claude Code, Copilot CLI, OpenCode and the other tools on this page can be pointed at the proxy as above, so everything an orchestrator runs counts in one usage log and stays within one set of budgets.

What was checked: Claude Code hooks and hook scripts taken from a real orchestrator's project were run here (a write refused, and allowed once the orchestrator's own condition held), and a project in Claude Code's layout (agents, skills, commands, hooks) loads with Maple Harness's own loaders. An orchestrator driving Maple Harness end to end was not run for this page.

Measure it yourself #

The measured comparison on this website is between Maple Harness and Copilot CLI. What the proxy changes for these tools on their own has not been measured, so this page gives no figure.

To measure it on your own work, use maple-harness bench. It can run another tool as one arm, with the same tasks and the same check, several times each: for example, the same tool once pointed at your model server directly and once at the proxy. The usage log shows what each request through the proxy cost.
