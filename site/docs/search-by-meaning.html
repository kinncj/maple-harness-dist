Search by meaning #

The agent looks things up with three tools: history_search (older parts of the conversation that were moved out of view to make room), recall (memory notes) and graph_search (the project index of files and symbols). On their own they match words, so a search for "the login bug" misses a message about "authentication failures after the upgrade". With a small embedding model set up in the proxy, each of these also ranks results by what they mean, and the two rankings are combined. Words still count: an exact match keeps its place.

It is optional. With no model set up, every search works exactly as it did before, and nothing extra is sent anywhere.

The proxy downloads both from Hugging Face at one fixed revision and checks every file against a checksum built into the proxy. A file that does not match is refused and nothing is installed. The weights are then converted to 8-bit, which keeps them small in memory, and the originals are deleted.

Choose the engine #

The Search by meaning card has two engines:

  • Built-in (Go): the proxy runs the model itself, on the CPU, with nothing else to install. Pick bge-small or EmbeddingGemma, download it, and press Use this model.
  • Your own server (OpenAI-compatible): the proxy sends the text to an embeddings server you already run on this machine or your own network, such as Ollama, oMLX, LM Studio or llama.cpp's server. Use this for a GPU, or for a model the proxy does not have built in.

Switching engines keeps the other engine's settings, so you can switch back. The config keys are listed in the proxy reference.

Set it up #

From the setup page: open the proxy's setup page, find the Search by meaning card, keep Built-in (Go) selected and press Download on bge-small-en-v1.5. The card shows the download's progress (with Cancel), this machine's memory and CPU cores, and a note if the machine is below what the model is comfortable on. It is installed as soon as the download finishes. There is no restart.

From a terminal:

maple-proxy embeddings list                        # the models, what is installed, and this machine
maple-proxy embeddings install                     # bge-small-en-v1.5
maple-proxy embeddings remove bge-small-en-v1.5

A running proxy picks up an install or a removal on its own. The harness notices within about half a minute and starts building its vectors in the background. A search made before they are ready still works, using words for whatever has no vector yet.

Use EmbeddingGemma built in #

EmbeddingGemma is gated on Hugging Face: Google asks everyone to accept its terms before downloading it.

  1. Sign in to Hugging Face, open the EmbeddingGemma 300M page and accept the terms there. Read the Gemma Terms of Use and the Gemma Prohibited Use Policy first.
  2. Create a token with read access at huggingface.co/settings/tokens, from the same account.
  3. On the card, paste it under Hugging Face token and press Save token. It is kept in the proxy's secret store (your system keyring when there is one) and is never shown again. For the terminal, set HF_TOKEN instead; when it is set it is used first.
  4. Press Download on EmbeddingGemma 300M (or run maple-proxy embeddings install embeddinggemma-300m), then Use this model (or set embeddings.builtin_model: embeddinggemma-300m).

The token is sent only to Hugging Face, and only for this model's download. The proxy adds the instructions EmbeddingGemma was trained with ("task: search result | query: …") for you. Switching models makes the harness build new vectors in the background; the old ones are not mixed in.

How close it is to the original: measured on 28 September 2026, the proxy's tokenizer gave exactly the same tokens as Hugging Face's own on all 104 test texts (several languages, code, emoji, runs of spaces and newlines), and its vectors matched those of the reference implementation (sentence-transformers) with a cosine similarity of at least 0.997 on each of 20 texts, 0.9994 on average. The small difference comes from the 8-bit weights.

Use your own server #

Any server with an OpenAI-compatible /v1/embeddings works, for example:

ServerBase URL (default port)Model name, for example
Ollamahttp://127.0.0.1:11434/v1embeddinggemma (after ollama pull embeddinggemma)
LM Studiohttp://127.0.0.1:1234/v1the embedding model you loaded
llama.cpp's llama-server (started with --embeddings)http://127.0.0.1:8080/v1the model it serves
oMLX, or another OpenAI-compatible serverits address, ending in /v1the embedding model it serves
  1. On the card, choose Your own server (OpenAI-compatible).
  2. Enter the base URL and the model's name. Enter an API key only if the server asks for one.
  3. Press Test: the proxy sends one short sentence and shows the length of the vector that comes back, or what went wrong and how to fix it. Then press Save and use.

maple-proxy embeddings test does the same from a terminal, for the server in config.yaml.

Only a server on this machine or your own network can be used: an address on loopback, a private range, a Tailscale address or a .local name, or one you tick as on my own network. Tick it only for an address you control. A provider already on the Providers card can be chosen instead of an address. A key is kept in the proxy's secret store and config.yaml holds only a reference to it. It is never shown again, and it is sent only to the address it was saved with: change the address and the card asks for the key again. If the model is one the proxy knows (EmbeddingGemma), its instructions are added for you.

Is my machine enough? #

The proxy reads the machine's total and free memory, its CPU cores, its processor type and operating system, and shows them on the card. Before a download it warns, and never blocks, when the machine is below these:

ModelComfortable fromBasis
bge-small-en-v1.54 GB of memory and 2 CPU coresmeasured: about 150 MB peak memory while working. One short passage takes about 125 ms on one core
EmbeddingGemma 300M (built in)more than 8 GB of memory, 4 or more CPU cores, and 1 GB freemeasured on one machine (below): about 0.4 GB of memory once loaded, up to about 0.7 GB while reading a 1,000-token passage

Speed of the built-in model, measured on one machine (a 16-core, 32-thread x86-64 processor, Linux), 28 September 2026:

EmbeddingGemma 300M built in, measured on the same machine the same day. It is a larger model, so it is slower:

10.33 s1.6 s15.9 snot measured

With many short texts at once, one per thread, it managed about 3 a second on 1 thread, 12 on 4 and 43 on 32. Converting it after the download took about 3 seconds and loading it well under a second on that machine. On a machine with few cores, building vectors for long notes and a large project index can take a long time: bge-small, or your own server with a GPU, is the better choice there.

Many short passages at once run one per thread. On the same machine that measured about 84 short passages a second with 32 threads, 26 with 4, and 7 with 1. Building vectors for a project index of about 7,100 files and symbols took about 1 minute 46 seconds, once, in the background. Loading the model takes well under a second. Your machine will differ. These are single-machine figures, not a promise.

What changes for the agent #

ToolWith a modelWithout one
history_searchResults ranked by words and meaning combined. The filters (role, tool, path, turn range) apply first, as beforeWords only, unchanged
recallGains a query argument that returns the eight closest notes by words and meaning. Without query it lists notes as beforeNo query argument; unchanged
graph_searchName matches, plus the files and symbols closest in meaning, combinedName matches only, unchanged

recall gets its query argument only when a model is set up at the time the session starts, so a session without one sees exactly the tool it always had.

Measured results #

A retrieval test, measured on 28 September 2026: queries worded differently from what they look for, over a 43-message coding conversation (24 queries), 24 project memory notes (16 queries), and this project's own index of about 7,100 files and symbols (16 queries). Each query was run twice through the real tools, words only and words plus meaning, and the target's position was compared. "Recall@1" is how often the target came first, "recall@5" how often it was in the first five.

StoreWords only @1 / @5bge-small @1 / @5EmbeddingGemma @1 / @5
Conversation history13/24 / 18/2417/24 / 20/2416/24 / 20/24
Memory notes8/16 / 11/1611/16 / 12/1612/16 / 14/16
Project index3/16 / 3/165/16 / 8/166/16 / 10/16

Per query, with bge-small, adding meaning moved the target up in 8 history queries, 6 note queries and 7 index queries, and down in one note query. It moved no target down in history or the index. With EmbeddingGemma it moved targets up in 8, 8 and 10, and down in none. Queries that share a distinctive word with their target were found first with words alone in 14 of 16 cases. Adding meaning kept them there or improved them.

Read these numbers with their limits:

  • One small test set, written by the maintainer, texts and queries both. It shows that combining helps on text worded differently. It is not a general benchmark.
  • The ranking is deterministic: running the test again gives the same numbers. Speed figures are from one machine. EmbeddingGemma ran in Ollama on that machine's integrated GPU; the built-in one gives nearly the same vectors (see above) and was not re-measured on this test.
  • For the memory notes, "words only" is the new query argument ranking by words, because recall had no search before.
  • Plain names such as quantize or ProjectRoot are what graph_search already finds. Adding meaning kept every one of them first.

Vectors for your own (user) memory notesmemory/.search-vectors in your Maple Harness config folderkept in step with the notes: a deleted note's vector goes the next time recall searches
Vectors for a project's memory notesvectors/<project>/memory.vec in your Maple Harness config folder, never inside the projectthe same. A .search-vectors file left in a project's .mapleharness/memory folder by an earlier version is no longer read, and can be deleted

Every vectors file is readable only by you, has a fixed size limit, is tied to the model that made it (a different model, or vectors of a different length, start a new one), and is written to a temporary file first and then renamed, never through a link. None of them holds any text, only numbers. If the harness stops in the middle of saving one, the temporary file it leaves (.vec- followed by digits) is removed by maple-harness cleanup once it is an hour old.

Privacy #

Text goes from the harness to the proxy it already uses, and no further than a model on this machine or your own network. The built-in models run inside the proxy. With your own server, the proxy forwards only to an address it can tell is local, and refuses one that is not. When it forwards, the proxy does not follow a redirect from that server to anywhere else, and it does not use the HTTP_PROXY or HTTPS_PROXY settings, so the text goes straight to the address you configured. Mark an address as local only if you control it. The Hugging Face token is sent only to Hugging Face, and not to the storage host Hugging Face hands a large download to. The embeddings endpoint on the proxy is behind the same protections as its other endpoints: open only to programs on this machine by default, and needing an access token when you open the proxy to your network (see Security). It works on one request at a time and holds at most four more waiting. A request past that is answered 429 with Retry-After: 2, and one whose caller has gone away leaves the queue. The harness only asks in small batches, so it does not meet this limit in normal use.
