    This is the complete list of what you can change on the proxy: the cards on its setup page, the keys in config.yaml, the commands, and the response headers you can read. For a guided tour, read The proxy and its setup page first.

    The proxy and the harness share one config.yaml. A save on the setup page keeps the harness: section and any setting the proxy does not know, and changes only the lines of the settings you changed, so your comments stay. Adding or removing a provider leaves the other providers as you wrote them; moving a provider up or down the list writes the provider list in the proxy's own layout, without its comments. Saves from the harness, the setup page and maple-proxy commands wait for each other, so none undoes another's change.

    Every setting has a Helps column, because each one exists to serve one or more of three goals:

    • Efficient: fewer tokens or AI units for the same work.
    • Efficacious: the work stays as good as it would be without the setting, and the defaults are safe.
    • Effective: whole tasks succeed: the right model answers, and waste is stopped before it grows.

    A setting is tagged only where that is true. Where a setting trades one goal against another, the trade-off is stated. Nothing here is a promise about your bill: measure your own tasks.

    Providers and models #

    A provider is a backend that serves models. The setup page's Providers card builds these for you; this is what the keys mean if you edit the file.

    KeyDefaultWhat it does
    providers[].idrequiredThe provider's name, for example github-copilot or ollama-main
    providers[].typerequiredWhat it is: github-copilot, anthropic, apple-foundation-models, openai-compatible, ollama, lmstudio, omlx, lemonade, unsloth. See Connect a model server
    providers[].base_urlthe type's usual addressWhere the server is
    providers[].api_keynoneA key, written as ${env:NAME} or ${secret:name} so it is never a plain value in the file. Keys you type into the setup page go to your system keyring. On the setup page a provider keeps its saved key while its address stays on the same server (the same scheme, host and port, however it is written: the usual port written out or not, upper or lower case); changing the address to a different server saves the provider without the key, so type the key again. An anthropic provider with no key of its own uses ANTHROPIC_API_KEY or the key saved by signing in, and a github-copilot provider uses your Copilot sign-in: the setup page refuses to move one to another server, or to add one at an address other than its own, unless you type that server's key (and, for Anthropic, ANTHROPIC_API_KEY is not set, since it is sent in place of a typed key). Providers written into config.yaml by hand, such as one at a company gateway, keep working as written. If a server redirects a request to another host, port or subdomain, the request is followed without the key; a redirect from https to http is refused. The setup page accepts a key you type or the reference the provider already has. A new ${env:NAME} or ${secret:name} is accepted there only when the page has a password set in a terminal with maple-proxy setup-password set (see More > Protect this page) and you are signed in with it in the browser; otherwise write it into config.yaml by hand. Without a password any program on this computer could open the page, and could also turn a password on from the page itself, so it could point a provider at another of your keys and send that key to a server of its choosing; a password set in a terminal shows that you did it. Maple's own commands, which reach the page without the password, cannot set a new reference either. The variable or secret must exist when you save. A reference to Maple's own credentials (the setup page's, or a stored sign-in) is never accepted. A new reference is the provider's key from that save on, so moving a provider to another server in the same save sends that reference's key there; sending back the reference it already had still counts as the saved key, and is dropped when the server changes
    providers[].nicknamenone (the provider's id is shown)What to call this account, for example work or personal; models are shown as work - gpt-5, or github-copilot - gpt-5 without one. It must differ from every other account's name and every provider id, whatever the type. Set by signing in with --as NAME, or by renaming on the setup page or with maple-proxy secrets rename. Display only: it never appears in model_fallbacks or a model's alias, which still name a provider by id
    providers[].localworked out from base_urlMarks this provider as running on your own machine or network. The proxy already treats localhost, private and link-local addresses that way; set this for a server reached by a name that does not show it, such as a machine on your network with its own host name. The harness treats a local model as costing nothing, for example when choosing who may summarise a long conversation
    providers[].optionalfalseIf the backend cannot be reached at start-up, log a warning and skip it instead of failing to start
    providers[].sidecar.command, providers[].sidecar.args, providers[].sidecar.socket_path, providers[].sidecar.dial_timeout_secondsdetectedFor apple-foundation-models only: how the on-device helper is started and reached. You rarely need these
    model_aliasesnoneShort fixed names for models, for tools that want a stable name. A model can also carry its own alias. Editable from the setup page's Model aliases card, or by hand in config.yaml

    Caching #

    Long conversations resend the same beginning on every turn. Providers that cache charge far less for the part they have already seen. These settings help that happen; the Cache card shows whether it did.

    KeySetup pageDefaultWhat it doesTrade-offHelps

    providers[].prompt_cache_keyCachingoffSends a stable cache key with each request to an OpenAI-compatible server, so a backend that supports it can route every turn of a conversation to the same cacheA server that does not know the field may reject the request, so it is opt-in per providerEfficient

    Images and browser snapshots #

    A model is charged for an image by its size in pixels, not by its file size, and a large image is scaled down by the provider before the model looks at it. Browser tools also return page snapshots (a text outline of the page) that are often the largest thing an agent resends. These settings shrink both. All of them are off by default.

    KeySetup pageDefaultWhat it doesTrade-offHelps
    image_resize_toolGuards, Images from toolsoffShrinks images a tool produced, such as a browser screenshot, before they are sent. provider_cap never sends more pixels than the model's provider says it uses; balanced scales large images down to about 1280 by 800 pixels' worth; aggressive to about 1024 by 640provider_cap costs the same tokens (the provider would have scaled the image down itself) and only saves upload size; it acts only for models whose provider publishes its rule (Claude, and OpenAI's tile-priced models such as gpt-4o and gpt-4.1), and only when the smaller file really is smaller. balanced and aggressive save tokens, and small text in a screenshot may become harder to read. They always send fewer pixels, but an image PNG had already squeezed very small (a repeating pattern, a screenshot with large flat areas) can come out larger in bytes; the report below shows the sizesEfficient (a trade-off above provider_cap)
    image_resize_userGuards, Images you attachoffThe same levels, for images you attach yourselfAs aboveEfficient (a trade-off above provider_cap)
    image_supersededGuards, Replace older tool imagesoffOnce a newer image from the same tool follows, replaces the older one with a one-line note. Images you attach are never replacedThe model can no longer see the older image. Each replacement changes an earlier message, so the provider re-reads what follows it once: with a provider that caches prompts this can cost more than it saves, and the Savings card counts those rewrites as a costEfficient (a trade-off)
    image_superseded_after_turnsGuards, Also after (turns)noneAlso replaces a tool image once this many of your turns have passed since it arrivedAs aboveEfficient
    snapshot_trimGuards, Trim browser snapshotsoffFor page snapshots from a browser tool (Playwright MCP): leaves out empty layout nodes, separators and images without a text alternative, folds runs of identical items into one line that still lists each item's reference, and, when the page did not change address since the last snapshot, sends only what changed since the last full snapshot of that page, with the nodes around each change. A new address, or a change too large for a list of changes to help, sends the full snapshotThe model reads changes against an earlier snapshot instead of a fresh full page. A result is only treated as a snapshot when it clearly is one; anything else is left exactly as it came. Recent Playwright MCP versions include the snapshot only in browser_snapshot results (after a click they link to a file, which is left alone), and a page that rebuilds its elements gets new references for all of them, so its next snapshot goes in fullEfficient (a trade-off)
    snapshot_trim_max_tokensGuards, Largest snapshot (tokens)12000A snapshot larger than this is cut, with a note saying how many lines were left outThe model does not see the end of a very large page until it asks for a smaller part of itEfficient

    When images are resized or replaced, the response carries X-Maple-Images with the count, the estimated tokens saved and the measured sizes before and after; the harness shows it as a note on screen (it is not sent to the model), and the proxy log has a line for each request with images, including the ones left untouched.

    Everything here gives the same result for the same conversation, so a conversation resent on every turn keeps using the provider's cache. An image that cannot be read, is rotated by its camera data, or is animated is sent as it came, and no image is ever made larger. The Savings card shows what each of these left out on its own line, as an estimate, and does not add it to the headline figure.

    Cost visibility #

    Copilot states what a call cost, in AI units, on every response. Anthropic's own API never does — it reports token counts only. /cost (see What /cost tells you) still shows a per-request figure for Anthropic when this is on, but it is a guess from Anthropic's published prices, not a bill, and is always shown labelled as one — real dollars, never added to the AI-units figure Copilot's calls carry.

    KeySetup pageDefaultWhat it doesTrade-offHelps
    providers[].estimate_costConfig fileoffFor a type: anthropic provider, prices each call from Anthropic's own published per-model rates, when Anthropic itself reported no price (it always does)The price list is read once, from this repository, not fetched live — if Anthropic's prices change, an old build's estimate is wrong until it is updated. Off by default: an estimate could be mistaken for what you were actually billedEfficacious

    Fallbacks #

    KeySetup pageDefaultWhat it doesTrade-offHelps
    model_fallbacksFallbacksnoneFor a model or alias, the names to try in order when it cannot answer: its account is out of chats or credit, the backend is overloaded, or it is unreachableA fallback may be a weaker or a different model, so results can differ. It happens only before any output is sent, and never for bad credentials or malformed requests. A fallback's own fallbacks are not followedEffective
    provider_fallbacksFallbacksnoneFor a provider (one signed-in account), where its requests go when it cannot answer: another provider id, which asks it for the same model, or <provider id>/<model>, which asks it for that model. Tried after the model's own model_fallbacks. Also used when the account itself is refused (signed out, or a seat removed)The same trade-offs as model_fallbacks. Only the chain of the provider serving the model you asked for is followed, not the chain of a fallback's provider. A provider id step is skipped when that provider does not serve the model. A later step may be a cloud provider, so a request a local provider cannot take goes thereEffective

    For example, two Copilot accounts, then Anthropic, then a local model:

    provider_fallbacks:
  github-copilot:           [github-copilot-personal, anthropic/claude-sonnet-5, local/qwen3-coder]
  github-copilot-personal:  [anthropic/claude-sonnet-5, local/qwen3-coder]

    When two accounts serve a model with the same name, a plain name goes to the last of them in the config (as in earlier versions; the proxy log says which), and <provider id>/<model> reaches a particular account's copy. This form works anywhere a model name does, including in model_fallbacks and as the model in a request, and the model list shows the other account's copy under it.

    Responses from a fallback say so in X-Maple-Fallback-From and name the model that answered in X-Maple-Served-By. A fallback whose known context window is too small for the request is passed over (the header says so), one whose window is unknown is still tried, and when nothing on the list fits, the request is refused with an error that says so.

    A model that has just answered that its account is out of quota is tried last for the next hour, so requests go straight to its fallbacks instead of waiting for the same refusal each time; X-Maple-Fallback-From names it with quota exhausted. It is not dropped: when everything else fails, or it has no fallbacks, it is still asked, and as soon as it answers again it goes back to its usual place. Without provider_fallbacks, that is the only thing the proxy remembers about a failure.

    For a provider that is part of a provider_fallbacks chain (the provider a chain starts from, or a step in one), the proxy remembers a little more, always in the same "tried last, never dropped" way:

    • Out of quota or credit: for as long as the provider's Retry-After says (at most a day), or an hour. Usually only that model is moved, because a Copilot account out of premium requests still answers with its included models; when the answer says the whole account has no credit or a billing problem, every model on it is moved.
    • Rate limited: for as long as Retry-After says, at most an hour, and only that model. A rate limit without Retry-After is not remembered.
    • Refused: for an hour. Every model on the account is moved only when the sign-in itself failed (bad or expired credentials, a revoked token, a suspended account). Any other refusal, such as a model your organisation's policy does not allow, moves only that model.
    • A Copilot account whose monthly chats are used up is moved before any request is spent on it, until the reset Copilot gives or for an hour, whichever is sooner; then it is asked again in its usual place, which also reads its meter afresh.

    Search by meaning #

    The proxy serves POST /v1/embeddings (the OpenAI request and response shape, up to 64 texts per request) and GET /v1/embeddings/info (which model answers, or why none does) on its OpenAI-compatible address, with the same protection as the rest of that address. With nothing installed or chosen, /v1/embeddings answers 503 with the reason. It works on one request at a time with at most four waiting; past that it answers 429 with Retry-After: 2. When it forwards to your server it follows no redirect and ignores HTTP_PROXY and HTTPS_PROXY, and an error from the server is reported in plain words with what to do, without the server's address, its key or its response text.

    The Hugging Face token for a gated built-in model is not a config key: save it on the card (it goes to the secret store) or set HF_TOKEN in the proxy's environment, which is used first.

    The setup page, card by card #

    CardWhat it shows and does
    AccountSign in to GitHub Copilot (a browser flow) or save an Anthropic API key. The Copilot plan and, where the plan has one, the chats left and when they reset
    ProvidersThe configured backends and their models. Add a server, press Detect models, edit or delete
    Remote accessThe master switch for remote control, access tokens for devices (short pairing codes, links, or fixed tokens), what each token may do, the folders a phone may start sessions in, and the gateway's addresses
    Proxy settingsCaching, Fallbacks, Guards, Budgets, and Limits and hosts: every setting above as forms and switches, with a Review changes diff before saving and a What this will do summary
    CacheThe provider cache's hit rate today, tokens read and written, AI units, a table per model and per client, and the moments the cache was lost with the likely reason
    SavingsWhat the proxy's techniques saved and cost, each figure marked measured or estimated, costs counted, and the net, which can be negative. Always shown next to what you actually spent (measured), and capped so it can never claim more was avoided than that. The net itself only ever totals the prompt cache and trimming — a fixed choice, no setting changes it; a couple of other techniques are shown on their own line but held out of the net until their own estimate can be checked against a real bill
    Search by meaningA status line (what answers, or what is wrong and how to fix it); this machine's memory, CPU cores and system; the engine switch. Built-in (Go): both models with their size, licence and a note when the machine is below what a model is comfortable on, Download with progress and Cancel, Use this model, Remove, and the Hugging Face token a gated model needs. Your own server: base URL, model, optional API key, Test and Save and use
    Protect this pageAn optional password for this page, off by default: Turn on (type it twice), change it, Sign out other browsers, Sign out, Turn off. See Protect the setup page with a password
    Recent activitySign-ins, token changes and switches

    Saved settings apply to the very next request with no restart, except those marked restart required. The page checks every value with the same rules the proxy uses at start-up, and points at the field that is wrong. Saving changes only the settings you changed in config.yaml, so hand-written comments are kept (see above for the one exception).

    Commands #

    maple-proxy with no command starts the server. The others:

    CommandWhat it does
    maple-proxy serveStart the proxy (the default). Flags: -config a config file; -logs where logs go (false, true, stdout, or a file path); -log-bodies also log prompt and answer text, which is off by default because a prompt to a coding agent is source code
    maple-proxy auth login <provider>Sign in to github-copilot (a browser flow) or anthropic (an API key). auth status shows what is signed in, auth logout <provider> forgets a credential
    maple-proxy secrets statusWhere each secret is stored, never its value. secrets migrate moves keys out of config.yaml into the secret store; --dry-run shows what would move
    maple-proxy cacheThe Cache card in a terminal. --recent lists the last requests, --json gives raw figures, --addr names the setup address
    maple-proxy cache probeSends the same small request twice and prints what each cost and how much came from the cache: a check you can run on your own account. It says what it will send and may spend a few AI units. -model, -tokens, -addr, -json
    maple-proxy savingsThe Savings card in a terminal: --json, --addr
    maple-proxy usage statusWhere the usage log is, whether it is on, how many days it keeps, and how much disk its daily files take (with the undated file from earlier releases, if any, counted apart, and an estimate at the retention limit). --path to look at another log
    maple-proxy usage exportWrite your usage log (every rotated file, or a --since/--until UTC-day range of them) to a CSV or Parquet file: --format csv\|parquet, --out FILE, --path to set the file directly instead of reading it from config.yaml (which, unset, means the default place). See Your usage data
    maple-proxy usage pruneDelete rotated usage-log files older than --keep-days N. Lists what it would delete first; nothing is removed without --yes
    maple-proxy usage schemaPrint the usage record's schema: --format json-schema (one log line), --format duckdb (column types), or --format sql (default: a DuckDB view named usage over the daily files, or over an export with --source csv\|parquet --path FILE). See The usage record schema
    maple-proxy embeddings listThe models for search by meaning, which is installed, their licences, and this machine's memory and cores with a note for any model it is below comfortable for. It also says which model the embeddings setting in config.yaml (or the file given with --config) chooses. Models are always kept in the config folder's embeddings/, whichever config file is used
    maple-proxy embeddings install [name]Download a built-in model (default bge-small-en-v1.5; or embeddinggemma-300m, which needs HF_TOKEN or a token saved on the setup page) at its fixed revision, check every file against its built-in checksum, and install it. Ctrl-C cancels and leaves nothing behind. embeddings remove <name> deletes an installed model
    maple-proxy embeddings testSend one short text to the embeddings server in config.yaml (embeddings.engine: server) and print the vector length, or what went wrong and how to fix it
    maple-proxy setup-passwordThe setup page's optional password: status, set (asked twice, not shown; --stdin reads one line from a pipe) and reset (removes it, so the page is open again; asks first unless --yes). A running proxy picks up the change at once
    maple-proxy audit tailThe newest entries of the audit logs: tokens made and revoked, keys saved, refused requests. -n how many, --json
    maple-proxy chatSend one prompt and print the answer, for a quick check that a model responds. -model and -prompt are required
    maple-proxy updateInstall a newer release. --check reports only
    maple-proxy versionThe version and how it was built
    maple-proxy licensesThe licences of the software inside the program. --summary lists the components

    mplp is a short name for maple-proxy.

    Response headers #

    The proxy adds these to responses so you can see what happened to a request.

    HeaderMeaning
    X-Maple-Served-ByThe provider and model that answered, for example github-copilot/gpt-6-sol
    X-Maple-Fallback-FromPresent when a fallback answered: the model that was passed over, and why
    X-Maple-Cachehit, partial, miss or lost: how the provider's cache did. Not sent on streamed responses
    X-Maple-Cache-Read, X-Maple-Cache-WriteTokens read from and written to the cache, where the provider reports them
    X-Maple-Prefix-StabilizedWhat the prefix stabiliser changed in the request, if anything
    X-Maple-Tool-Results-TrimmedHow many old tool results were replaced, and about how many tokens
    X-Maple-ImagesHow many images were resized or replaced by a note, and about how many image tokens that left out (an estimate from the provider's published rule)
    X-Maple-Snapshots-TrimmedHow many browser page snapshots were recognised, how many were sent as changes only or cut, and about how many tokens that left out
    X-Maple-Context-TrimmedPresent when the context guard dropped old turns to fit the model's window
    X-Maple-ClientSent by the harness so its requests can be told apart from other tools' in the Cache card
    X-Maple-SessionSent by a client (the harness sends it automatically) so its requests, and any subagent's, group together on the Sessions card
    X-Maple-Usage-RowsOn a download from the setup page's Usage data card: how many requests the exported file holds
    X-Maple-Usage-SchemaOn the same download: the version of the usage record schema the file follows
    X-Maple-Config-BaseOn the setup page's raw configuration: which version of the file it shows. Sent back with a save, a copy that is out of date is refused, so it cannot undo a change made since

    Files and environment #

    WhereWhat
    versionThe configuration file's format version, currently 1
    ~/.config/maple-harness/config.yamlThe proxy's and the harness's settings
    ~/.config/maple-harness/embeddings/The installed built-in model for search by meaning, one folder per model, private to you
    ~/.config/maple-harness/setup-page-password.jsonThe setup page's password as a salted hash, and its signed-in browsers, private to you. Absent when the page has no password
    ~/.config/maple-harness/access.jsonAccess tokens (hashed) and the remote-control switch. Managed by the setup page
    Your system keyringProvider keys and sign-ins. Without a keyring, a private file with the same protection, and the proxy says so
    ~/.config/maple-harness/usage/maple_harness_proxy_usage_ledger-YYYY-MM-DD.jsonlThe usage log, one file per UTC day, private to you (or <usage_ledger>-YYYY-MM-DD.jsonl when server.usage_ledger names another path; none when it is off). One JSON object per request (see Your usage data): at, duration_ms, requested, model, provider, streamed, tools, messages, input_tokens, output_tokens, cached_tokens, cache_write_tokens, ai_units, error, client, agent, surface, conv, fallback, cache_class, cache_reason (types and meanings: the usage record schema).
