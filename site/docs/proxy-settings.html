Proxy reference: every setting #

This is the complete list of what you can change on the proxy: the cards on its setup page, the keys in config.yaml, the commands, and the response headers you can read. For a guided tour, read The proxy and its setup page first.

Every setting has a Helps column, because each one exists to serve one or more of three goals:

  • Efficient: fewer tokens or AI units for the same work.
  • Efficacious: the work stays as good as it would be without the setting, and the defaults are safe.
  • Effective: whole tasks succeed: the right model answers, and waste is stopped before it grows.

A setting is tagged only where that is true. Where a setting trades one goal against another, the trade-off is stated. Nothing here is a promise about your bill: measure your own tasks.

Providers and models #

A provider is a backend that serves models. The setup page's Providers card builds these for you; this is what the keys mean if you edit the file.

KeyDefaultWhat it does
providers[].idrequiredThe provider's name, for example github-copilot or ollama-main
providers[].typerequiredWhat it is: github-copilot, anthropic, apple-foundation-models, openai-compatible, ollama, lmstudio, omlx, lemonade, unsloth. See Connect a model server
providers[].base_urlthe type's usual addressWhere the server is
providers[].api_keynoneA key, written as ${env:NAME} or ${secret:name} so it is never a plain value in the file. Keys you type into the setup page go to your system keyring. On the setup page a provider keeps its saved key while its address stays on the same server (the same scheme, host and port); changing the address to a different server saves the provider without the key, so type the key again. The setup page accepts a key you type or the reference the provider already has; any other ${env:NAME} or ${secret:name} goes into config.yaml by hand
providers[].nicknamenone (shown as "default")What to call this account when more than one of the same type is configured, for example work or personal. Set by signing in with --as NAME, or by renaming on the setup page or with maple-proxy secrets rename. Display only: it never appears in model_fallbacks or a model's alias, which still name a provider by id
providers[].localworked out from base_urlMarks this provider as running on your own machine or network. The proxy already treats localhost, private and link-local addresses that way; set this for a server reached by a name that does not show it, such as a machine on your network with its own host name. The harness treats a local model as costing nothing, for example when choosing who may summarise a long conversation
providers[].optionalfalseIf the backend cannot be reached at start-up, log a warning and skip it instead of failing to start
providers[].sidecar.command, providers[].sidecar.args, providers[].sidecar.socket_path, providers[].sidecar.dial_timeout_secondsdetectedFor apple-foundation-models only: how the on-device helper is started and reached. You rarely need these
model_aliasesnoneShort fixed names for models, for tools that want a stable name. A model can also carry its own alias. Editable from the setup page's Model aliases card, or by hand in config.yaml

Caching #

Long conversations resend the same beginning on every turn. Providers that cache charge far less for the part they have already seen. These settings help that happen; the Cache card shows whether it did.

KeySetup pageDefaultWhat it doesTrade-offHelps
providers[].prompt_cacheCaching, a switch per providerautoMarks the reusable parts of a request for backends that need telling (Claude through the Anthropic API, or through Copilot). off sends requests unmarkedOff saves nothing and is only for troubleshootingEfficient
providers[].prompt_cache_keyCachingoffSends a stable cache key with each request to an OpenAI-compatible server, so a backend that supports it can route every turn of a conversation to the same cacheA server that does not know the field may reject the request, so it is opt-in per providerEfficient
providers[].echo_reasoningConfig fileoffSends the model's earlier reasoning back to an OpenAI-compatible server that returns it (for example a self-hosted reasoning model), so the model continues from its own thinking during a task instead of re-deriving where it was. Only the task in progress sends itA server that does not know the field may reject the request, so it is opt-in per provider. Measured on one model only (Qwen3.8 on vLLM) and not yet on others, so try it on your own tasks with maple-harness benchEfficient, Effective
prefix_stabilizerGuardsautoKeeps the start of a request identical from turn to turn for tools that do not manage their own caching: it restores a tool list to its first order, and moves a changing line such as the current time to the end of the last messageChanges the position of one line of text in requests from such tools; it never removes or rewrites a tool, and it leaves a request alone when the tool marks its own cache points. off disables itEfficient, Efficacious
context_trimGuardsoffOnce a conversation is long, replaces the content of old, large tool results with a short note, a batch at a timeAnything trimmed is gone from the model's view: it may ask for it again, which costs a request. context_trim_after_tokensGuards60000The estimated conversation size at which trimming beginsA lower value trims sooner and rewrites the cached start more oftenEfficient
context_trim_keep_recent_turnsGuards6How many of the latest turns are never trimmedA higher value keeps more context and saves lessEfficacious
context_trim_min_result_tokensGuards1000The smallest tool result worth replacingA lower value trims more, smaller resultsEfficient
cache_warmingCachingoffWhile a conversation sits idle, sends a small refresh so the provider's cache does not expire before your next message arrives — so that message still gets the cheaper, cached price instead of paying to rewrite the cache from scratch. Only for providers where the proxy knows the vendor's own cache lifetime; today that is Anthropic's built-in cacheIt spends a little to try to save more later, and does not always pay off — if you were about to send your next message anyway, the refresh bought nothing. cache_warming_min_savings_ai_unitsCaching0.05The smallest expected saving worth sending a refresh forLower sends more refreshes, some of which will not pay offEfficient
cache_warming_continuation_probabilityCaching0.15How often you send your next message before the cache would have expired anyway, so a refresh turns out to have been unnecessary. A starting estimate, not measured on your own traffic yetHigher makes the feature more cautious about sending refreshes at allEfficient

Images and browser snapshots #

A model is charged for an image by its size in pixels, not by its file size, and a large image is scaled down by the provider before the model looks at it. Browser tools also return page snapshots (a text outline of the page) that are often the largest thing an agent resends. These settings shrink both. All of them are off by default.

KeySetup pageDefaultWhat it doesTrade-offHelps
image_resize_toolGuards, Images from toolsoffShrinks images a tool produced, such as a browser screenshot, before they are sent. provider_cap never sends more pixels than the model's provider says it uses; balanced scales large images down to about 1280 by 800 pixels' worth; aggressive to about 1024 by 640provider_cap costs the same tokens (the provider would have scaled the image down itself) and only saves upload size; it acts only for models whose provider publishes its rule (Claude, and OpenAI's tile-priced models such as gpt-4o and gpt-4.1), and only when the smaller file really is smaller. balanced and aggressive save tokens, and small text in a screenshot may become harder to readEfficient (a trade-off above provider_cap)
image_resize_userGuards, Images you attachoffThe same levels, for images you attach yourselfAs aboveEfficient (a trade-off above provider_cap)
image_supersededGuards, Replace older tool imagesoffOnce a newer image from the same tool follows, replaces the older one with a one-line note. Images you attach are never replacedThe model can no longer see the older image. Each replacement changes an earlier message, so the provider re-reads what follows it once: with a provider that caches prompts this can cost more than it saves, and the Savings card counts those rewrites as a costEfficient (a trade-off)
image_superseded_after_turnsGuards, Also after (turns)noneAlso replaces a tool image once this many of your turns have passed since it arrivedAs aboveEfficient
snapshot_trimGuards, Trim browser snapshotsoffFor page snapshots from a browser tool (Playwright MCP): leaves out empty layout nodes, separators and images without a text alternative, folds runs of identical items into one line that still lists each item's reference, and, when the page did not change address since the last snapshot, sends only what changed since the last full snapshot of that page, with the nodes around each change. A new address, or a change too large for a list of changes to help, sends the full snapshotThe model reads changes against an earlier snapshot instead of a fresh full page. A result is only treated as a snapshot when it clearly is one; anything else is left exactly as it came. Recent Playwright MCP versions include the snapshot only in browser_snapshot results (after a click they link to a file, which is left alone), and a page that rebuilds its elements gets new references for all of them, so its next snapshot goes in fullEfficient (a trade-off)
snapshot_trim_max_tokensGuards, Largest snapshot (tokens)12000A snapshot larger than this is cut, with a note saying how many lines were left outThe model does not see the end of a very large page until it asks for a smaller part of itEfficient

Everything here gives the same result for the same conversation, so a conversation resent on every turn keeps using the provider's cache. An image that cannot be read, is rotated by its camera data, or is animated is sent as it came, and no image is ever made larger. The Savings card shows what each of these left out on its own line, as an estimate, and does not add it to the headline figure.

Cost visibility #

Copilot states what a call cost, in AI units, on every response. Anthropic's own API never does — it reports token counts only. /cost (see What /cost tells you) still shows a per-request figure for Anthropic when this is on, but it is a guess from Anthropic's published prices, not a bill, and is always shown labelled as one — real dollars, never added to the AI-units figure Copilot's calls carry.

KeySetup pageDefaultWhat it doesTrade-offHelps
providers[].estimate_costConfig fileoffFor a type: anthropic provider, prices each call from Anthropic's own published per-model rates, when Anthropic itself reported no price (it always does)The price list is read once, from this repository, not fetched live — if Anthropic's prices change, an old build's estimate is wrong until it is updated. Off by default: an estimate could be mistaken for what you were actually billedEfficacious

Fallbacks #

KeySetup pageDefaultWhat it doesTrade-offHelps
model_fallbacksFallbacksnoneFor a model or alias, the names to try in order when it cannot answer: its account is out of chats or credit, the backend is overloaded, or it is unreachableA fallback may be a weaker or a different model, so results can differ. It happens only before any output is sent, and never for bad credentials or malformed requests. A fallback's own fallbacks are not followedEffective

Responses from a fallback say so in X-Maple-Fallback-From and name the model that answered in X-Maple-Served-By. A fallback whose known context window is too small for the request is passed over (the header says so), one whose window is unknown is still tried, and when nothing on the list fits, the request is refused with an error that says so.

The usage log #

KeySetup pageDefaultWhat it doesHelps
server.usage_ledgerUsage data, Turn on (or Limits and hosts, Usage log)offA file that receives one line of numbers per request: model, tokens, cache figures, AI units, timing. Budget counts come from it (the Cache, Sessions and Savings cards now survive a restart on their own, without it). It holds counts and labels only, never prompts or answers. Turn on in the Usage data card sets it to usage.jsonl in your Maple Harness config folder (you can change the path first). Turning it on, moving it or turning it off from the setup page applies at once, without a restart, unless CCH_USAGE_LEDGER is set; a path that cannot be written is refused with the reasonEfficient (it makes spend visible)

Search by meaning #

Which model ranks the harness's searches by meaning. See Search by meaning for what it does, both models, their licences (EmbeddingGemma is under the Gemma Terms of Use and the Gemma Prohibited Use Policy, and its download needs a Hugging Face token from an account that accepted them) and hardware guidance: EmbeddingGemma built in is comfortable with more than 8 GB of memory and 4 or more CPU cores.

KeySetup pageDefaultWhat it doesHelps
embeddings.engineSearch by meaning, the engine switchbuilt in, unless base_url or provider is setbuiltin (a model that runs inside the proxy) or server (your own OpenAI-compatible embeddings server). With builtin, the server settings below are kept for switching back. Applies without a restartEffective
embeddings.builtin_modelSearch by meaning, Use this modelbge-small-en-v1.5Which built-in model answers: bge-small-en-v1.5 or embeddinggemma-300m. It must be installedEffective
embeddings.base_urlSearch by meaning, Your own server, Base URLnoneYour embeddings server's OpenAI-compatible address, for example http://127.0.0.1:11434/v1 for Ollama. An address that is not on this machine or your own network is refused. No user name, password or query in itEffective
embeddings.modelSearch by meaning, Your own server, ModelnoneThe model's name at that server or provider, for example embeddinggemma. Required when embeddings.base_url or embeddings.provider is setEffective
embeddings.api_keySearch by meaning, Your own server, API keynoneSent to that server as a bearer token. The setup page keeps it in the secret store and writes ${secret:embeddings/api_key} here. Written into the file by hand, ${env:EMBEDDINGS_NAME} (a variable whose name starts with EMBEDDINGS_) works too; no other reference is used for this key. Never shown back, and cleared when the server's address changesEffective
embeddings.localSearch by meaning, This address is on my own networkfalseVouches that base_url is on your own network when its name alone does not show it. Set it only for an address you controlEffective
embeddings.providerSearch by meaning, Your own server, Or usenoneInstead of base_url: the id of a local OpenAI-compatible provider from the Providers card whose /v1/embeddings answers. Its own key is used. A provider that is not on this machine or your own network is refusedEffective

The proxy serves POST /v1/embeddings (the OpenAI request and response shape, up to 64 texts per request) and GET /v1/embeddings/info (which model answers, or why none does) on its OpenAI-compatible address, with the same protection as the rest of that address. With nothing installed or chosen, /v1/embeddings answers 503 with the reason. It works on one request at a time with at most four waiting; past that it answers 429 with Retry-After: 2. When it forwards to your server it follows no redirect and ignores HTTP_PROXY and HTTPS_PROXY, and an error from the server is reported in plain words with what to do, without the server's address, its key or its response text.

The Hugging Face token for a gated built-in model is not a config key: save it on the card (it goes to the secret store) or set HF_TOKEN in the proxy's environment, which is used first.

The setup page, card by card #

CardWhat it shows and does
AccountSign in to GitHub Copilot (a browser flow) or save an Anthropic API key. The Copilot plan and, where the plan has one, the chats left and when they reset
ProvidersThe configured backends and their models. Add a server, press Detect models, edit or delete
Remote accessThe master switch for remote control, access tokens for devices (short pairing codes, links, or fixed tokens), what each token may do, the folders a phone may start sessions in, and the gateway's addresses

Always shown next to what you actually spent (measured), and capped so it can never claim more was avoided than that. The net itself only ever totals the prompt cache and trimming — a fixed choice, no setting changes it; a couple of other techniques are shown on their own line but held out of the net until their own estimate can be checked against a real bill
Search by meaningA status line (what answers, or what is wrong and how to fix it); this machine's memory, CPU cores and system; the engine switch. Your own server: base URL, model, optional API key, Test and Save and use
Recent activitySign-ins, token changes and switches

Saved settings apply to the very next request with no restart, except those marked restart required. The page checks every value with the same rules the proxy uses at start-up, and points at the field that is wrong. Saving rewrites config.yaml in its standard form, so hand-written comments are not kept.

Commands #

maple-proxy with no command starts the server. The others:

CommandWhat it does
maple-proxy serveStart the proxy (the default). Flags: -config a config file; -logs where logs go (false, true, stdout, or a file path); -log-bodies also log prompt and answer text, which is off by default because a prompt to a coding agent is source code
maple-proxy auth login <provider>Sign in to github-copilot (a browser flow) or anthropic (an API key). auth status shows what is signed in, auth logout <provider> forgets a credential
maple-proxy secrets statusWhere each secret is stored, never its value. secrets migrate moves keys out of config.yaml into the secret store; --dry-run shows what would move
maple-proxy cacheThe Cache card in a terminal. --recent lists the last requests, --json gives raw figures, --addr names the setup address
maple-proxy cache probeSends the same small request twice and prints what each cost and how much came from the cache: a check you can run on your own account. It says what it will send and may spend a few AI units. -model, -tokens, -addr, -json
maple-proxy savingsThe Savings card in a terminal: --json, --addr
maple-proxy usage exportWrite your usage log (every rotated file, or a --since/--until UTC-day range of them) to a CSV or Parquet file: --format csv\|parquet, --out FILE, --path to set the file directly instead of reading it from config.yaml. See Query and export your usage data
maple-proxy usage pruneDelete rotated usage-log files older than --keep-days N. Lists what it would delete first; nothing is removed without --yes
maple-proxy usage schemaPrint the usage record's schema: --format json-schema (one log line), --format duckdb (column types), or --format sql (default: a DuckDB view named usage over the daily files, or over an export with --source csv\|parquet --path FILE). See The usage record schema
maple-proxy embeddings listThe models for search by meaning, which is installed, their licences, and this machine's memory and cores with a note for any model it is below comfortable for. It also says which model the embeddings setting in config.yaml (or the file given with --config) chooses. Models are always kept in the config folder's embeddings/, whichever config file is used
maple-proxy embeddings install [name]Download a built-in model (default bge-small-en-v1.5; or embeddinggemma-300m, which needs HF_TOKEN or a token saved on the setup page) at its fixed revision, check every file against its built-in checksum, and install it. Ctrl-C cancels and leaves nothing behind. embeddings remove <name> deletes an installed model
maple-proxy embeddings testSend one short text to the embeddings server in config.yaml (embeddings.engine: server) and print the vector length, or what went wrong and how to fix it
maple-proxy audit tailThe newest entries of the audit logs: tokens made and revoked, keys saved, refused requests. -n how many, --json
maple-proxy chatSend one prompt and print the answer, for a quick check that a model responds. -model and -prompt are required
maple-proxy updateInstall a newer release. --check reports only
maple-proxy versionThe version and how it was built
maple-proxy licensesThe licences of the software inside the program. --summary lists the components

mplp is a short name for maple-proxy.
