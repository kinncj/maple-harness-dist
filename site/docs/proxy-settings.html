    This is the complete list of what you can change on the proxy: the cards on its setup page, the keys in config.yaml, the commands, and the response headers you can read. For a guided tour, read The proxy and its setup page first.

    The proxy and the harness share one config.yaml. A save on the setup page keeps the harness: section and any setting the proxy does not know, and changes only the lines of the settings you changed, so your comments stay. Adding or removing a provider leaves the other providers as you wrote them; moving a provider up or down the list writes the provider list in the proxy's own layout, without its comments. Saves from the harness, the setup page and maple-proxy commands wait for each other, so none undoes another's change.

    Every setting has a Helps column, because each one exists to serve one or more of three goals:

    • Efficient: fewer tokens or AI units for the same work.
    • Efficacious: the work stays as good as it would be without the setting, and the defaults are safe.
    • Effective: whole tasks succeed: the right model answers, and waste is stopped before it grows.

    A setting is tagged only where that is true. Where a setting trades one goal against another, the trade-off is stated. Nothing here is a promise about your bill: measure your own tasks.

    In plain words #

    • What it is. The complete list of the proxy's settings, cards, commands and response headers.
    • What to do. On the setup page you rarely need this page: each card explains itself, Advanced lists every setting with its default and when it applies, and Find a setting finds one by a word. Come here for the exact key, the default and the trade-off.

    Images and browser snapshots #

    A model is charged for an image by its size in pixels, not by its file size, and a large image is scaled down by the provider before the model looks at it. Browser tools also return page snapshots (a text outline of the page) that are often the largest thing an agent resends. These settings shrink both. All of them are off by default.

    KeySetup pageDefaultWhat it doesTrade-offHelps
    image_resize_toolGuards, Images from toolsoffShrinks images a tool produced, such as a browser screenshot, before they are sent. provider_cap never sends more pixels than the model's provider says it uses; balanced scales large images down to about 1280 by 800 pixels' worth; aggressive to about 1024 by 640provider_cap costs the same tokens (the provider would have scaled the image down itself) and only saves upload size; it acts only for models whose provider publishes its rule (Claude, and OpenAI's tile-priced models such as gpt-4o and gpt-4.1), and only when the smaller file really is smaller. balanced and aggressive save tokens, and small text in a screenshot may become harder to read.     image_resize_userGuards, Images you attachoffThe same levels, for images you attach yourselfAs aboveEfficient (a trade-off above provider_cap)
    image_supersededGuards, Replace older tool imagesoffOnce a newer image from the same tool follows, replaces the older one with a one-line note.     When images are resized or replaced, the response carries X-Maple-Images with the count, the estimated tokens saved and the measured sizes before and after; the harness shows it as a note on screen (it is not sent to the model), and the proxy log has a line for each request with images, including the ones left untouched.

    Everything here gives the same result for the same conversation, so a conversation resent on every turn keeps using the provider's cache. An image that cannot be read, is rotated by its camera data, or is animated is sent as it came, and no image is ever made larger. The Savings card shows what each of these left out on its own line, as an estimate, and does not add it to the headline figure.

    Cost visibility #

    Copilot states what a call cost, in AI units, on every response.     X-Maple-Config-PathSent by a maple-proxy command that tells the running proxy about a change it saved: the configuration file it wrote. The proxy applies the change only when that is its own file, and otherwise keeps its configuration

    ~/.config/maple-harness/chain-bindings.jsonWhich proxy each proxy-chain token is bound to, private to you. Absent until a chain token is bound. Kept apart from access.json so that going back to a 1.x release does not unbind them

The program gets a minimal environment, not the proxy's (see the data lake's troubleshooting)
