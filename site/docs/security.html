Security #

An agent runs commands and writes files on your machine; that is its job. This page says what Maple Harness does to keep that safe, and what you should do.

Reporting a problem #

Email Kinn Coelho Juliao at <kinncj@gmail.com> with what you found, how to reproduce it, and the version (maple-harness version). Please allow a reasonable time to respond before disclosing it publicly. Reports are handled in confidence.

What it does for you #

  • It asks first. Every tool call passes your rules. By default it asks before writing a file or running a command, and a deny rule is absolute. --yolo skips the asking, never the denying, and it must be given on the command line: a configuration file can never turn it on by itself.
  • The shell can be contained. With bubblewrap on Linux (optional) or the built-in sandbox on macOS, shell commands can write only in your project, cannot see your credentials, and run with a scrubbed environment. While a session is shared for remote control the shell also has no network unless you allow it. See Install.
  • The file tools keep out of secrets. They refuse your SSH keys, cloud credentials and shell history, and write only in your project, the temp directory and folders you list.
  • Your sign-ins stay out of the config. Keys go in your system keyring, and the configuration holds only a reference.
  • The setup page is local. It listens on this machine only, and refuses to listen anywhere else.
  • Devices get their own tokens. Each paired device has its own token that you can limit to some folders and revoke at any time. Pairing codes work once and expire in five minutes.
  • Downloads are checked. The installer and update verify every file against the release's SHA256SUMS.

What you should do #

  • Treat a device token like an SSH key. It is a shell on your computer. Prefer pairing codes, keep tokens out of chats and screenshots, and revoke a lost phone straight away.
  • Use Tailscale, or another private network, for remote control. Do not forward the port through your router to the internet. See Remote control.
  • Install bubblewrap on Linux if you share a session or run untrusted projects, and run maple-harness doctor to confirm the sandbox works.
  • Only add MCP servers you trust. A server that runs as a program on your machine has your permissions.
  • Use --yolo only in a throwaway checkout or a container.
  • Keep it up to date: maple-harness update.

A model can be steered by text in a file it reads or a web page it is shown, and nothing can make a model reliably ignore hostile text. The permission prompts are your protection, so read them.

The models you configure receive what you send them. With Apple's on-device model or a local server, nothing leaves your machine; with a cloud provider, your prompts and any file content the agent sends go to that provider.

maple-harness doctor checks that these protections are in place on your machine.
