Troubleshooting #

Start with the checker. It looks at your configuration, the proxy, sign-ins, ports, remote control and the sandbox, and says what to do about each problem it finds:

maple-harness doctor                      # add --fix to repair file permissions and stale files
maple-harness doctor --report bug.txt     # a redacted bundle to attach when you ask for help

Two commands inside a session answer most of the rest:

/proxy      where the proxy is, whether it answers, how many models it serves
/context    what the model can see: window size and how full it is

maple-proxy serve --logs=true shows every request and the reason behind every failed one.

The proxy #

The agent says the proxy is unreachable. Nothing answers at the configured address. /proxy shows where the agent is looking, and /proxy start starts one. This usually means server.openai_compat in config.yaml differs from where a proxy was started.

The setup page at 127.0.0.1:11539 does not load. Check the proxy is running. server.webui in config.yaml sets its address, and an empty value turns the page off. The page only listens on this machine; from another device, use remote control.

Port already in use. The defaults are 11535, 11537 and 11539. Find what holds one with lsof -i :11539, then stop it or change the address under server: in config.yaml.

Signing in #

Copilot sign-in never finishes. Open the link it printed and enter the code within ten minutes, then run maple-harness auth login github-copilot again. A 403 means the account has no Copilot seat, or the grant was revoked; signing in again is the first thing to try.

"This account has no chat models enabled for Copilot". The account is signed in but nothing it lists is usable. On an organisation's seat, check the Copilot policies your organisation set.

Copilot: model_not_supported. The free plan does not let an account call most models by name; they are served through auto mode. Signing in configures this for you, so run maple-harness auth login github-copilot again to refresh, and only the models that work are written. Remove any model you added by hand that fails this way.

Anthropic: "credit balance too low". The key is valid and the account has no API credit. Add credit under Plans and Billing in the Anthropic Console. API credit is separate from a claude.ai or Claude Code subscription, which is not an API key.

Anthropic: "rejected that API key". Anthropic refused the key, so nothing was stored. Check it was copied whole and belongs to an account with API access.

The quota meter is missing. It appears only when the current model's provider has a metered account. It is absent for local models. Sign in first, and note that before the first request only what is left is known.

Models #

The context window shows 0, or history is trimmed too early. A window of 0 means unknown. Leave context_window out of config.yaml so the proxy asks the server, and check /context. If the server reports nothing, set it by hand.

A local model repeats itself or stops without finishing. Small models do this. Use them for scoped work, such as a function, a file or a fix, start a fresh session per task, and use /compress when one grows long.

The model says it "can't build the whole project in one run". Small and cheap models sometimes decline a long task they are able to do. Maple Harness answers once with a nudge to start step by step, and says so ("continuing — the model declined a task it can do"). If the model declines again it tells you which model it is and suggests a stronger one with /model <name> (or pinning models with auto_model_map, see models). With /model auto, a model that declined is skipped for the rest of the session.

Auto keeps picking a model that declines. Auto avoids models known to decline long tasks and remembers ones that do (maple-harness doctor lists them; maple-harness cleanup --declines --yes forgets them). To choose yourself, use /model <name>, pin models with auto_model_map, or add patterns to auto_avoid in config.yaml. A model you choose yourself is never blocked by any of this.

Detect models finds nothing. The address must include the API prefix (/v1, or /api/v1 for Lemonade), and the server must be running. Choose the matching type in the picker so its usual address is filled in.

Installing and updating #

checksum mismatch. The installer stops and leaves the existing files untouched. A truncated download is the usual cause; run it again.

permission denied writing to /usr/local/bin. Use --install-location ~/.local/bin, or run the installer with sudo.

macOS says a downloaded binary cannot be opened. Binaries downloaded by hand are not notarised yet. Right-click and choose Open, or use the installer, which avoids this.

Remote control #

The phone cannot reach the address. Check both devices are on the same Tailscale network (or the same local network for a LAN address) and that a firewall is not blocking port 11541.

Pairing shows a link that does not load. The gateway may have stopped. /remote pair starts it again; or run maple-harness gateway start.

A phone lists sessions but + New session is refused. No folder is allowed yet: maple-harness gateway workspaces add <dir>.

A session does not appear in the phone's list. Share it with /remote in that session.

The gateway or proxy is gone after a reboot. Install them as services: maple-harness service install. See Running as a service.

Notifications do not arrive with the page closed. That needs a trusted HTTPS certificate; see Remote control. maple-harness doctor says which certificate the gateway is using.

429 from the proxy on another machine. Requests from other machines are rate-limited. Slow down, or ask the owner to raise server.rate_limit in config.yaml.

The shell sandbox #

/sandbox says bubblewrap is missing, or installed but not working. It is optional; the install command for your system is in Install. "Installed but does not work" usually means unprivileged user namespaces are blocked, for example in a container. Until it works, commands run uncontained.

A command fails inside a shared session because it has no network. While a session is shared for remote control, the shell has no network unless you allow it: /sandbox network allow, or set harness.sandbox.network: allow in config.yaml.

sh: fork: Resource temporarily unavailable. Fixed in current builds; update with maple-harness update and restart the agent.

Disk space #

The configuration directory (~/.config/maple-harness) holds saved sessions, memory notes and logs. To see how much it uses and clear old sessions, run maple-harness cleanup --help.
